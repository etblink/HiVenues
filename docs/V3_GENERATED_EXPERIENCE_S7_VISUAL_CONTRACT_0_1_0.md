# HiVenues v3 Generated Experience — S7 Visual Contract 0.1.0

Status: FROZEN S7.0 CONTRACT

## 1. Provenance and scope

This contract opens PM4 S7 (`GENERATED_EXPERIENCE_VISUAL_CONVERGENCE`) from the exact canonically qualified S6 baseline:

```text
ENTRY_COMMIT = b6b4bbfe1d46d0926a6026f897dcd00f28197312
ENTRY_TREE   = 5870f6a862bb6fce6f9096eb024a647b7c3bbe2b
GOVERNING_ISSUE = #226
CONDITIONAL_BREADTH_ISSUE = #224
```

S7 changes the generated visitor experience. It does not reopen the S6 Studio product contract, semantic source authority, persistence/provenance model, provider boundaries, or conditional breadth by default.

## 2. Baseline finding

The S6 baseline is semantically mature and visually underdeveloped by design.

The v3 visitor surface already has one shared renderer family for the frozen R1/R2/R3 references and correctly carries page, activity, temporal, presence, lifecycle, access, action, managed-media, business-fact, and route semantics. Its public stylesheet is deliberately small: system typography, a simple header, flat bordered surfaces/cards, basic buttons, straightforward image treatment, and one narrow-viewport breakpoint.

Therefore the S7 problem is presentation convergence, not semantic reconstruction.

## 3. North star

**Warm editorial hospitality, premium restraint, clear venue identity, and quiet utility.**

The generated experience should read as a polished venue publication / boutique hospitality site rather than an operator dashboard. The venue owns the experience; HiVenues remains subordinate provenance.

## 4. Frozen invariants

S7 implementation MUST preserve all of the following:

1. One host-general semantic renderer family across R1 migrated physical, R2 locationless creator, and R3 release references.
2. Canonical source data remains the sole semantic authority; presentation code may not mutate it.
3. Existing page/component/activity order remains source-defined and stable-id driven.
4. Physical facts appear only when present in canonical source; online/release hosts must not fabricate place facts.
5. Existing action roles, destinations, presence, lifecycle, temporal forms, access, and managed-media semantics remain intact.
6. The real generated renderer remains the Studio preview source.
7. Keyboard operability, visible focus, minimum interactive target size, reduced-motion safety, semantic headings/landmarks, and responsive semantic order remain mandatory.
8. Rendering remains side-effect free: no implicit Hive RPC/write, provider write, signing, payment, or deployment behavior.
9. No remote font, analytics, image, or presentation dependency may be introduced merely for visual polish.
10. S7 may not create separate R1/R2/R3 renderers, host-name branches, or independent desktop/mobile semantic trees.
11. #224 remains conditional. Missing breadth may be promoted only when evidence demonstrates the target cannot be represented honestly with the existing vocabulary.

## 5. Visual contract

The shared visitor renderer should converge on these qualities.

### 5.1 Venue-first identity

- The venue display name is the primary site identity.
- Navigation is legible and restrained rather than application-like chrome.
- HiVenues product identity must not compete with the venue in the public hierarchy.

### 5.2 Editorial hierarchy

- Heading scale and measure communicate a clear reading order.
- Body copy remains comfortably readable at desktop and narrow widths.
- Kicker/eyebrow/status metadata is subordinate to titles and primary content.
- Section rhythm comes from spacing and typography before boxes or decorative chrome.

### 5.3 Premium spacing and surfaces

- Content uses a deliberate maximum reading/site width.
- Whitespace groups related information and separates major sections.
- Borders, radii, shadows, and surface fills are restrained and structural.
- Cards/pills are not the default treatment for every block.

### 5.4 Media-led composition

- Existing Hero and activity media receive stable, intentional aspect treatment.
- Images remain responsive, preserve canonical alt behavior, and never require an external presentation service.
- Missing media degrades gracefully without fabricated imagery.

### 5.5 Participation/action hierarchy

- Primary actions are visually obvious and comfortably targetable.
- Secondary participation/location/navigation actions remain distinct without competing with the primary conversion path.
- Status, access, capacity, temporal, and presence facts remain readable and truthful.

### 5.6 Responsive continuity

- Narrow layouts preserve the same semantic story and source order.
- Navigation, media, text, and actions reflow without horizontal overflow.
- Responsive behavior may alter composition, not semantic content or authority.

### 5.7 Accessible restraint

- `:focus-visible` treatment remains conspicuous.
- Interactive controls retain at least 44px target height where the current contract requires it.
- Reduced-motion behavior remains safe.
- Color and decoration may not become the sole carrier of semantic state.

## 6. Implementation ownership boundary

S7 presentation work belongs primarily in the shared public renderer/style layer (`src/venue/v3/renderer/index.js`). Small host-general markup hooks are allowed only when needed to express the frozen visual contract and only if existing semantics remain unchanged.

S7 presentation code MUST NOT acquire:

- source mutation or authoring authority;
- persistence authority;
- provider/value execution authority;
- Hive write/signing authority;
- host-specific semantic selection authority.

## 8. Qualification contract

Every substantive S7 candidate must retain the existing deterministic/unit renderer gates and the real-browser cross-host journeys. Visual acceptance additionally requires evidence from representative R1/R2/R3 generated experiences at desktop and narrow viewports.

At minimum qualification must establish:

- no host-specific renderer branch;
- semantic/source digest preservation;
- route/action/presence/temporal/media behavior unchanged unless separately authorized;
- zero unintended external effects;
- no horizontal overflow at qualified viewports;
- no blocking accessibility findings;
- visible focus and target-size guardrails preserved;
- visual hierarchy materially improves over the S6 baseline rather than merely changing colors;
- no #224 promotion without an evidence-bound rationale.

## 9. Stop/routing rule

A visual defect that reveals a genuinely missing semantic capability is recorded and routed; it is not faked in CSS or hard-coded per host. S7 closes only after the generated R1/R2/R3 experiences form one coherent, materially improved 2026 visitor language and the exact candidate plus post-merge qualification are green.
